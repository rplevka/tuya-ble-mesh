# Tuya P2 Mesh Native Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a native Home Assistant integration that controls the Tuya Beacon Mesh P2 bulbs over local raw-HCI Bluetooth, with a key/config wizard, full light features, and no cloud or MQTT at runtime.

**Architecture:** One config entry per adapter/home stores the home beacon key and a list of bulbs. A raw-HCI transport advertises flags-first P2 frames and scans for reports. A controller owns sequence persistence and serializes radio access. Light entities map DP 1/2/3/4/11 to on/off, brightness, white temperature, and HSV colour. The first live validation runs in a minimal Home Assistant container on the laptop with the Intel AX201; the NAS deployment waits for a USB Bluetooth adapter.

**Tech Stack:** Python 3.14, Home Assistant 2026.11.x, pytest, pytest-homeassistant-custom-component, Podman, raw HCI sockets.

**Spec:** `docs/superpowers/specs/2026-11-26-tuya-p2-mesh-design.md`

## Global Constraints

- No runtime Python dependencies; vendor/adapt the MIT raw-HCI code with attribution.
- Never commit or log local keys, beacon keys, MAC addresses, or device IDs. Tests use synthetic keys and vectors only.
- P2 advertisements must be exactly `02 01 06 1b 03 <26-byte frame>`; Flags must come first.
- Source ID defaults to `0x7D00`. Seed the sequence from the existing bridge or `0x4000`; persist before every transmission. Do not run the bridge and the integration against the same bulbs at the same time.
- DP map: 1 switch, 2 mode, 3 brightness (4-byte, 10..1000), 4 temperature (4-byte, 0..1000), 11 colour (4-byte raw HSV: H big-endian 2 bytes, S, V; S/V 0..100).
- Runtime must not use Tuya cloud, MQTT, the Tuya gateway, or an external bridge.
- Entity state is optimistic. P2 is one-way; do not claim physical acknowledgement.
- Raw HCI access is the only transport. The adapter is expected to be dedicated to this integration.
- The lab test stops `tuya-p2-bridge.service`; restart it after the test.
- The new integration is the repository’s single HACS integration; the old diagnostic probe moves to `tools/diagnostics/` in the final cleanup task.
- Home Assistant version: 2026.11.x. Python 3.14 in the container.

## Review Focus

- **Adapter unavailable or permission denied:** setup must fail with a clear `RadioError` and an unavailable entity, never crash Home Assistant. Tested in Task 2.
- **Sequence reset or rollover:** a restart must not reuse or regress the counter; commands must not silently become no-ops. Tested in Task 4.
- **Malformed or foreign BLE advertisements:** the scanner must ignore them safely. Tested in Task 2.
- **Wrong or missing keys / capture mismatch:** capture and test steps must fail cleanly, redact secrets, and keep the flow usable. Tested in Tasks 1 and 6.
- **Concurrent commands / adapter contention:** radio access must be serialized; no interleaved advertising state. Tested in Task 4.

```python
def derive_beacon_key(frame: bytes, local_key: bytes, known_payload: bytes) -> bytes:
    if len(frame) != P2_FRAME_LEN:
        raise ValueError("P2 frame must be 26 bytes")
    if frame[0] != 0x0B or frame[7] != 0x05:
        raise ValueError("not a P2 DP command")
    plaintext = known_payload.ljust(16, b"\0")
    if crc8(plaintext) != frame[8]:
        raise ValueError("known payload does not match frame CRC")
    encrypted = xxtea_encrypt(plaintext, key_bytes(local_key))
    beacon = bytes(a ^ b for a, b in zip(frame[9:25], encrypted))
    if not p2_outer_crc_ok(frame, beacon):
        raise ValueError("invalid P2 outer CRC")
    return beacon
```

- [ ] **Step 3: Implement `controller.py`**

- `SequenceStore` reads/writes a small JSON file atomically; `next`
  increments the counter, saves, and returns the new value. Store the
  value as an integer. The controller calls
  `await asyncio.to_thread(self.sequence.next)` so file I/O stays off the
  event loop.
- `P2Controller.send` encodes DPs, gets the next sequence, builds the
  frame with `p2.build(1, 5, self.source_id, bulb.node_id, seq, payload,
  bulb.local_key, self.beacon_key)`, and awaits `radio.advertise`.
- Use an `asyncio.Lock` around radio operations.
- `scan` calls `radio.scan`, parses each raw `RawAdvertisement.data`
  into a P2 frame, and returns `P2Advertisement` entries; ignore
  malformed or non-P2 ads.
- `capture_beacon_key` scans for frames whose destination is `node_id`
  and whose source is not the node, requires frame type 1/subcommand 5,
  and tries `DP_OFF_PAYLOAD` and `DP_ON_PAYLOAD`. It collects derived
  keys and returns only when both derive to the same key. Ignore bulb
  reports and any frame whose plaintext CRC does not match DP1. Raise
  `CaptureError` with a user-safe message otherwise.
- `test` sends DP 1 ON and OFF to the bulb, then returns.
