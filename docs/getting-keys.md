# Finding the bulb's MAC, local key, and node ID

The native integration needs a few values that are not all visible in the
Tuya app. This guide explains where each one comes from and which ones the
wizard can learn for you.

The Tuya app/cloud is used **once per bulb** for pairing and key retrieval.
After the integration has the keys, runtime is local.

## Summary

| Value | Where it comes from | Wizard behavior |
| --- | --- | --- |
| Bluetooth MAC | Bulb label/box, Tuya IoT platform device/factory details, sometimes the app's device details | Scan or manual entry |
| Local key | Tuya IoT platform (or a Tuya account QR login, not yet in this version) | Manual entry (a future version will fetch it automatically) |
| Node ID | The P2 mesh address, learned from the app's OFF/ON command advertisements | Scan label or manual entry |
| Beacon key | Captured locally from the app's OFF/ON frames | Automatic capture step |

**Do not post the local key or beacon key in an issue, screenshot, or log.**
Treat them like passwords. They can change if the bulb is removed and
re-paired.

## Bluetooth MAC address

The easiest and most reliable source is the **label or box** of the bulb. It
is usually printed as a 12-character address such as `DC:23:50:...`.

Other sources:

- Tuya IoT platform: **Devices → All Devices → device details / factory
  info**. The factory-info API also returns the MAC.
- The Tuya app's device information screen, when it shows one.
- A Bluetooth scan, when the bulb is advertising.

Be careful with the integration's **Discover** scan: an advertisement from
the phone/app command relay uses a rotating address, not the bulb's own MAC.
Do not use that address as the bulb MAC unless it is the address printed on
the bulb. Enter the label MAC in the manual field instead.

## Local key

The Tuya app does **not** display the local key. It is a 16-character secret
generated by Tuya. The supported way to get it in this version is the Tuya
IoT platform:

1. Sign in at <https://platform.tuya.com>.
2. Create or open a **Cloud project** in the same data center as your app
   account (for example Central Europe). The free IoT Core service is enough.
3. In the project, use **Devices → Link App Account** and scan the QR code
   with the Tuya app. This gives the project read access to your devices.
4. Open **Devices → All Devices**, select the bulb, and open its device
   details. The response contains `local_key`.
   - If the portal does not show it directly, use **Cloud → API Explorer →
     Query Device Details**, paste the device ID, and read `local_key` from
     the response.
5. Copy the 16-character key into the integration's **Local key** field.

The bulb can be offline in the cloud; the local key is still shown.

The local key is specific to the current pairing. If you remove and re-add
the bulb in the app, fetch the new key.

A future version of the integration will offer a Tuya account QR login in the
wizard to fetch the local key automatically. That is a convenience; the
runtime remains local.

## Node ID

The node ID is the bulb's 16-bit address in the P2 mesh. It is **not shown in
the Tuya app or the cloud device list** for standalone BLE bulbs; the cloud
field is usually empty.

Learn it from the radio:

1. In the integration's **Discover** step, start the scan.
2. Toggle the bulb **OFF and ON** in the Tuya app, with the phone close to
   the Home Assistant adapter.
3. The scan lists the advertisements it hears. An app command appears with a
   line such as:

   ```text
   5A:...:1F  (-60 dBm, node 1234)
   ```

   The `node 1234` value is the P2 destination, i.e. the bulb's node ID.
4. Do not use `node 8000` or `node 8001`: those are broadcast destinations
   used by bulb reports, not a bulb address.
5. Enter the app-command node in the **Node ID** field (hex, for example
   `1234`), and use the bulb's label MAC in the MAC field.

If the scan does not show an app command, toggle the bulb again and rescan.
Bulbs do not advertise while idle, so the app toggle is the trigger.

The node ID can change if the bulb is removed and re-added to the app.
Recheck it after re-pairing.

## Beacon key

The beacon key is home-wide. The integration's **Capture the beacon key**
step learns it locally by watching for the app's OFF and ON frames while you
toggle the bulb. You do not need to obtain it from Tuya.

If you already have the beacon key, you can paste it into the optional field
instead of capturing it. Do not share it.

## If discovery does not hear anything

- The integration must own a local Bluetooth adapter. Home Assistant
  Bluetooth proxies/ESPHome/Shelly are scan-only and cannot be used for
  transmission.
- On a shared adapter, BlueZ or Home Assistant's Bluetooth integration may
  hold the LE scan state. Use a dedicated USB adapter for this integration,
  or stop BlueZ while scanning. The NAS deployment guide explains the
  validated container recipe.
- Keep the phone and bulb close to the adapter while toggling the bulb.
